# FASE 2 — Esquema PostgreSQL

## Estado

FASE 2 implementada a nivel de artefactos y verificación estructural. No se ha conectado ni modificado una instancia PostgreSQL de producción.

## Cambios realizados

- Se creó `worker-secondary/db/migrations/001_initial_schema.sql`.
- Se creó `worker-secondary/install-postgres.sh`.
- Se creó `worker-secondary/verify-postgres-schema.mjs`.
- Se mantuvieron nombres de tablas/columnas compatibles con el contrato D1 auditado.
- Se añadieron PK, FK, índices y constraints principales.
- Los IDs usan `GENERATED BY DEFAULT AS IDENTITY`.
- Los timestamps de infraestructura usan `TIMESTAMPTZ`.
- Se conservan como `TEXT` los campos cuyo formato actual es parte del contrato de aplicación (por ejemplo `fecha_partido` y campos JSON/texto), evitando cambios prematuros de contrato.

## Decisiones importantes

No se convirtieron automáticamente todos los `0/1` a `boolean`, ni todos los JSON de `TEXT` a `jsonb`, porque eso podría romper consultas y respuestas actuales. Esa optimización puede hacerse posteriormente con una migración compatible y tests de contrato.

## Instalación

Requiere `DATABASE_URL` y `psql`.

```bash
cd worker-secondary
./install-postgres.sh
node verify-postgres-schema.mjs
```

## Limitación

La auditoría se realizó sobre el código/migraciones disponibles en el ZIP. Para declarar equivalencia de datos al 100% todavía hace falta ejecutar la instalación contra una instancia PostgreSQL real y comparar el catálogo de la base y, posteriormente, los datos migrados desde D1.
